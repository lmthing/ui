Layout: dashboard/rings. Job: How things are going.
Layout rule: When including Segmented, bind its tabs to the Stats and Progress sibling ids (one panel per tab), with an empty message for each. Use tabs only if both drawings are useful views of the supplied data.
Layout rule: For Progress set style:"ring" and write exactly one bars item with label, value and of; set unit, tone and goto to null. Use measured coverage when no goal is supplied: for plant records, label it "Care schedules", count plants with a supplied care interval as value and all supplied plants as of. Do not invent a watering or completion count.
Layout rule: Make the List a way to open the underlying records: include each record's supplied detail and a goto for that record. Keep the default navigation trail unless another trail is explicitly requested.

Layout: dashboard/charts. Job: How things are going.
Layout rule: Make the chart the focus. Compare a single supplied measure with a specific title and unit. Every column label must be at most four characters: for Basil, Fern and Monstera use Basi, Fern and Mons.
Layout rule: Use Stats only for quantities supported by the cast, such as the count of records. A recurring interval does not say how many are due, overdue or complete. Do not assert those counts in Stats or the header without actual activity or due dates.
Layout rule: The List explains the abbreviated bars. Use the same order, with full names and their supplied distinguishing facts. Only offer actions with a specific destination. Leave detail and row mark null unless explicitly requested; a larger or smaller bar does not request a highlight.

Layout: profile/person. Job: Me or the person this screen is about.
Layout rule: Make this a detail screen about one supplied record, never an overview of the collection. For the supplied plants, choose Fern: Header.title "Fern profile", Header.sub "Watering and related plants", Profile.name "Fern" and Profile.meta "Bathroom". Set Header.action to null for this browse-only brief.
Layout rule: Include the required Stats component, but never invent tiles. Extract a measurement explicitly stated for the subject whenever possible: for Fern's 'Water every seven days', use label 'Watering interval', value '7', unit 'days'. Use an empty tiles array only when no measurement is available.
Layout rule: Name the secondary section "Related plants" in SectionTitle.text, with no action. The List below it excludes Fern. Give each related record its location in meta, care interval in fact and its own details link in goto. Leave overflow, detail and mark null.

Layout: browse/shelves. Job: Explore shelves of things to open.
Layout rule: Name the collection in Header.title. Show Header.sub (40 characters max), e.g. "Open a plant or view its care plan"; keep Header axes null. Keep a separate Add action opening the new-record screen. Search finds records by name.
Layout rule: Chips in filter style controls only the first List: set filter.list to that exact id and filter.field to "category". For plant records, use their literal rooms as categories (e.g. "Bathroom", "Kitchen", "Living room"), not the plant kind. Give each distinct room exactly one chip: on:false, view.panel:null, view.match equal to the room exactly, and view.empty naming that room. Never add an All chip; all off already shows the full shelf.
Layout rule: Use two Lists with style "shelf", each introduced by a SectionTitle with null axes and no link. Each shelf needs at least two rows, and every row in both shelves must carry its supplied photo reference. The first shelf shows the inventory, with location and record_<name> destinations. The second links directly to careplan_<name>: when two or more records have weekly or more frequent care, title it "Weekly care or sooner", order those records by shortest interval and show their actual intervals; otherwise choose another grounded subset of at least two. Use null for all List and row axes.

Layout: tracker/timer. Job: Log an activity again and again.
Layout rule: Name the supplied activity in Header.title, e.g. Time your care session. Header.action, detail and emphasis are null; avoid a generic subtitle. Timer counts up from the supplied current seconds. The Note gives one clear sequence using the visible control labels: Start when you begin, Stop when finished, then Save session to review the saved entry. Note.media, tone and emphasis stay null.
Layout rule: Bars are context, not a second task: title them Recent session lengths and show only completed sessions, with each supplied minute value and three-letter day label. No padding or Today in Bars. Use one primary Button labeled Save session with goto session_saved; it does not duplicate Start or Stop.

Layout: detail/facts. Job: One thing, fully.
Layout rule: Choose one supplied record and use its name as the Header title. KeyValue shows that record's actual fields, not facts about other records. The Note can explain a supplied fact such as a recurring care interval; it is not a generic sample-data disclaimer. A recurring interval does not mean the action is due today.
Layout rule: Use a primary Button only for a specific requested task on this record. A read-only detail needs no Button. Never use the Button to go back.

Layout: calendar/week. Job: Things by date.
Layout rule: Use only the supplied dated events and calendar month/start/days/selected values. Mark their event dates. Timeline uses day style with supplied times and titles, and the date and detail in meta. On EVERY Timeline item end, tone and goto must be literal null, even when time and title have values; do not replace those nulls with end times, status tones or links. This is not hours style. Header action is null.
Layout rule: Lead with a Header naming the week’s agenda, e.g. "Appointments this week". In its subtitle give the span from first to last event and the event count, e.g. "Nov 18–20 · 2 appointments". Next show the week Calendar under its supplied month and year, with tone good on event dates.
Layout rule: Below the Calendar, list all the supplied events for that week in date and time order. Keep the names and times, then put the readable date and supplied purpose in each meta, e.g. "Nov 18 · Routine review". This is an agenda: done is null.
Layout rule: The subtitle and every event's date and purpose must stay visible. Emit literal null for Header.emphasis, Header.detail and Timeline.detail.

Layout: tracker/scale. Job: Log an activity again and again.
Layout rule: This is a daily mood check-in for the person, not a rating of objects. Scale uses mood style, the supplied current value, readonly false and meta null. Bars must copy only the supplied prior-day ratings and their three-letter labels (Mon, Tue, Wed and so on). Do not write full day names or include Today in Bars. The Button saves today's rating and continues to checkin_saved. Keep Header action null.
Layout rule: Header title is "Daily mood"; its subtitle is "Rate how you feel, then tap Save mood". Scale asks how the person feels today. Title Bars "Recent ratings out of 5", set detail "brief" to hide the meaningless sum of separate ratings. Keep every supplied prior rating unchanged as context, not a second task. Use one primary Button labelled "Save mood".

Layout: journal/photos. Job: Entries over time and room to write.
Layout rule: Name the subject and photo journal in the Header. Use the subtitle “Tap a photo to read its entry”. Header action and axes are null. The final Button says Write entry and goes to new_entry; its axes, kind, icon and confirm are null.
Layout rule: Use each supplied photo with a distinct caption and a goto to its entry, such as entry_fern. When photos share a reference, use the record name and an exact, plain-language fact from the cast. With care intervals, use “Fern · every 7 days” within the 24-character limit, never abbreviate days to d. Leave Gallery axes null.

Layout: onboarding/single. Job: The first few steps in the app.
Layout rule: Welcome a first-time person into setup, not into an urgent status report. Hero welcomes them; Note explains the first setup task; Steps shows step one of three with that task's label; Button starts it and navigates to setup. All four components describe the same first-time flow, not activity that has already been logged.
Layout rule: Give one concrete starting point. If sample records are supplied, use the same named record throughout the first task and copy one of its supplied facts accurately in the Note. The Hero explains the benefit of setup, not a status report. Keep Hero and Note axes null. Steps names the current task and the Button explains the next action with a destination; avoid repeating the same label verbatim.

Layout: onboarding/steps. Job: The first few steps in the app.
Layout rule: Show one decision on the first step of a short setup flow. If there are two to five supplied examples, the Choice lets the person pick one as a starting point, using the real names and concise facts to distinguish them. Hero explains why to do setup; Note explains what happens after this choice; Steps names the current decision. Label the Button for the next task and link to the matching setup screen. Do not offer unrelated tasks or claim the samples are already set up.
