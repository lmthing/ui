Layout rule: Make the List a way to open the underlying records: include each record's supplied detail and a goto for that record. Keep the default navigation trail unless another trail is explicitly requested.

Layout: dashboard/charts. Job: How things are going.
Layout rule: Bars columns have labels of at most four characters, even when the source name is longer. Abbreviate every category consistently; keep full names in the following List. Compare one meaningful measured unit.
Layout rule: The List explains the abbreviated bars. Show each full name and its supplied detail. Leave detail and row mark null unless explicitly requested; a larger or smaller bar does not request a highlight.

Layout: browse/shelves. Job: Explore shelves of things to open.
Layout rule: Write two Lists with style "shelf". Each shelf needs at least two rows, each with its supplied photo and a goto to the record. An icon or lead value cannot replace a photo. If the records cannot fill two shelves separately, reuse supplied photo records rather than making a photo-less or single-row shelf.
Layout rule: Give the shelves different jobs. For example, the first can help find records by location and the second can show their supplied care routines. Match each heading to that shelf's row meta; if a record appears twice, the second row must add a different supplied fact. Search and Chips help find records; do not use the second shelf for a copy of the first or invent recency or status.

Layout: tracker/timer. Job: Log an activity again and again.
Layout rule: The Timer measures the current supplied session, using seconds. A short Note explains Start, Stop and saving the finished session. Bars show exactly the supplied completed sessions, using each record's minutes and three-letter day label. Do not pad the chart with missing days or zeroes; Today belongs only in the Timer. The Header may link to completed-session history; leave its action null if there is no useful history destination. The Button saves the finished session; it does not duplicate Start or Stop.

Layout: detail/facts. Job: One thing, fully.
Layout rule: Choose one supplied record and use its name as the Header title. KeyValue shows that record's actual fields, not facts about other records. The Note makes a supplied fact useful for the next action, such as a recurring care interval; it is not a generic sample-data disclaimer. Label the Button to log or manage that record and link to the matching next screen. A recurring interval does not mean the action is due today.

Layout: calendar/week. Job: Things by date.
Layout rule: Use only the supplied dated events and calendar month/start/days/selected values. Mark their event dates. Timeline uses day style with supplied times and titles, and the date and detail in meta. On EVERY Timeline item end, tone and goto must be literal null, even when time and title have values; do not replace those nulls with end times, status tones or links. This is not hours style. Header action is null.
Layout rule: Give the week a recognizable date in the Header and say what is scheduled. Arrange the supplied events in date and time order. Keep each item's supplied purpose or detail beside its date and time so the agenda says what each event is for.

Layout: tracker/scale. Job: Log an activity again and again.
Layout rule: This is a daily mood check-in for the person, not a rating of objects. Scale uses mood style, the supplied current value, readonly false and meta null. Bars must copy only the supplied prior-day ratings and their three-letter labels (Mon, Tue, Wed and so on). Do not write full day names or include Today in Bars. The Button saves today's rating and continues to checkin_saved. Keep Header action null.
Layout rule: Make the sequence clear: Header says to rate today's mood and save it; Scale asks how the person feels today; Bars is titled as recent mood ratings and labels the same rating unit; the primary Button says Save mood. Keep prior ratings as context, not a second task.

Layout: journal/photos. Job: Entries over time and room to write.
Layout rule: Make this a photo journal, not a catalog of interchangeable images. Use the supplied photos and name each record in its Gallery caption. If the same photo reference is shared, use a short supplied detail beside the name to distinguish the entries; keep each caption within 24 characters. Tapping a photo opens that record. The final Button writes a photo journal entry; it is the only creation action.

Layout: onboarding/single. Job: The first few steps in the app.
Layout rule: Welcome a first-time person into setup, not into an urgent status report. Hero welcomes them; Note explains the first setup task; Steps shows step one of three with that task's label; Button starts it and navigates to setup. All four components describe the same first-time flow, not activity that has already been logged.
Layout rule: Give one concrete starting point. If sample records are supplied, name one and use a real detail to show what the person can set up, without claiming they already did. Use the Hero for the benefit of setup, the Note for this practical example, and the Button for the specific first action. Do not repeat the same instruction in each component.

Layout: onboarding/steps. Job: The first few steps in the app.
Layout rule: Show one decision on the first step of a short setup flow. If there are two to five supplied examples, the Choice lets the person pick one as a starting point, using the real names and concise facts to distinguish them. Hero explains why to do setup; Note explains what happens after this choice; Steps names the current decision. Label the Button for the next task and link to the matching setup screen. Do not offer unrelated tasks or claim the samples are already set up.
