# Component guide

How to build one component of `@lmthing/ui`. `src/components/List.tsx` and `List.test.ts` are the
reference: copy their shape exactly. The plan (`implementation-plan.md` 4.2, 4.4, 4.13, 5.4 to 5.6)
says what each component is; this guide says how its file is written.

## What one component is

Exactly two files, plus recordings:

| File                                | Holds                                                                  |
| ----------------------------------- | ---------------------------------------------------------------------- |
| `src/components/<Id>.tsx`           | `meta`, `props`, `fallback`, `examples`, `probes`, and the view `<Id>` |
| `src/components/<Id>.test.ts`       | schema, fallback and probe-shape tests                                 |
| `test/recordings/<Id>/<model>.json` | recorded model replies from `pnpm llm:check --component <Id>`          |

Nothing else is registered by hand. Entries, the renderer map, conformance tests and the gallery pick
the file up from the folder. `<Id>` is the PascalCase id from the lists in `docs/catalog/` (plan 4.4).

## The file, in order

For a new catalog entry, start with `pnpm gen:component <pack|core> <Name>` from `packages/ui`
(or `pnpm --filter @lmthing/ui gen:component <pack|core> <Name>` from the workspace root).
It reads the named section of `docs/catalog/`, writes a `draft` component and test, and
creates component-specific copy and English label keys. It leaves existing components,
including their probes, alone. For a pack, it also wires the component through the pack door.
Use explicit types (`text(n)`, `number`, `integer`, `boolean`, dates and references),
backticked enum choices, and explicit array bounds (`items` of fields, `1–6`). Name
shared axes in `Styles`, for example `density: comfortable, compact` with the values
in backticks. Ambiguous shorthand, nested repeated collections, conditional schemas
and custom runtime state names may need to be scaffolded by hand.

Check the draft against the full entry before building the view: supply real examples,
replace the probe prompts and check the read address, implement conditional actions and
variant part changes, and move the label keys into the owning `lang/en.ts` dictionary.
The generated view is only a placeholder, not evidence for the model or visual gates.

1. **Imports.** Only `zod`, `../catalog` and `../kit`. Never `tamagui`, `react-native` or lucide
   directly: those live behind kit bases.
2. **`meta`**: a plain object, `as const satisfies Meta`.
   - `purpose` ≤ 16 words, about the person's need, not the widget.
   - `pick`: when to choose it, then "Not …" naming the nearest wrong component(s) by id.
   - Optional `writeHints` explain cross-field rules that the compact schema signature omits, using valid examples.
   - `region`, `weight`, `tier`, `realPath` (one sentence) from `docs/catalog/` and the component's current schema/metadata.
   - `items` (only if it repeats): `{ key, parts }`. `parts`, `states`, `actions` list exactly what
     the view draws and what a person can do. `partTiers` and `confirmParts` name declared parts;
     `dense` marks dense pack components. `codeOwned` excludes a component from choose/write prompts.
     No `meta.aliases`: strict `writerFormat(registry)` limits `c` and props to the scoped schemas
     (the 2026-11-18 design). Renamed or merged ids keep migration aliases through `legacyTarget`.
   - `select` declares the selected prop, row value (`index`, `position`, or `{ field }`), optional row `flags` mode and fixed named `parts` values.
   - `items.toggles: { save: "saved" }` maps a named item toggle at `rN/save` to a boolean row field. Also declare `save: ["toggle"]` in `actions.items`. The store value overlays the addressed row before `live.derive` and `items.visibleWhen`; it does not change wire props. Use `useLiveControls` to draw from the same live rows.
   - `items.readSecrets: { fields, when }` replaces matching row fields with `(secret)` in the agent read, including after a visual reveal. Bind a row reveal toggle to its current content with `items.revealSecrets: { part, fields }` and read the grant with `secretRevealMatches`; a reused address does not reveal replacement content. Do not pass secret text as an action value.
   - For a masked credential, declare the value with `kind: "secret"` and bind the named component toggle with `actions.credentialToggles: { reveal: "memberId" }`. Use `credentialToggleOn` with the control value and current credential; an old or serialized grant does not disclose a different credential. The read exposes the action and its state, never the full credential.
   - `live.toggles: { details: { prop: "expanded", initial: false } }` maps a component `toggle` or `check` declared in `actions.parts` (including `root`) to a live boolean. A parsed boolean overrides `initial`; `toggle` and `check` share the value. Each part owns a distinct prop. The overlay runs before `live.derive`, item visibility and action gates; read and `useLiveControls` use the projected boolean, not the first boolean in the schema. Use host acknowledgement for authoritative remote state.
   - `localState: defineLocalState({ schema, initial, events, itemEvents, reduce, project })` declares a pure instance reducer. Both event lists use `part.action`; also declare these actions in `actions.parts` or `actions.items`. The reducer receives the previous state and a validated `{ part, action, item?, value }` (an addressed row id for an item event). Return `{ state }` or a safe `{ error }`. Keep rules and bounded history in the component, use a bounded JSON state schema without transforms, and derive `initial` only from the parsed seed. The last committed state is used only for a matching seed. Reading a different seed shows its initial state but does not erase progress; the first committed event on that seed replaces it. Use a distinct instance id for a different round with identical seed props. `project` explicitly returns only public props for `useLiveControls`, `live.derive`, gates and `meta.read`; do not project hidden state or replace wire-owned `state`. Local events own their mutation: do not combine them with other runtime mechanisms on the same action. Reuse `draw` or `session` for simple rolls, grades and turns.
   - For a puzzle, use `trustedSeed(publicProps)` to look up the solution or category map by public board id. Only `reduce(state, event, trustedSeed)` sees it. Keep a public board revision in `initial`, never a solution or an encoding of it. Store and project only reader-safe facts, such as progress and the score of an attempted entry. Missing seeds and trusted reducer failures return generic errors. Test reads and stored state before solve, after solve, after reset and after failure.
   - Cached but usable content (such as an offline observation or radar frame) stays `filled`, not a new wire state. Read the cached value and its observation timestamp from validated, declared host records. Project a trusted stale flag with `deviceDataFlags`, and gate fresh-only actions using `actions.when`. Keep usable local controls and the cached timestamp visible in the view and agent read. Use `error` when no usable snapshot is available.
   - `clocks` on meta, items or items.nested declares time sources, live props, start/stop/reset and zero behavior. `adjust` on meta or items maps `"part.action"` to `{ prop, delta, min?, max? }` for a numeric prop or live clock; see `src/catalog/meta/README.md` and keep projected values inside the prop schema's bounds.
   - `items.nested: { key, parts: { [part]: { action: "toggle" | "set", prop, min?, max?, integer?, when? } } }` declares `rN/<part>_M` controls projected into sub-items; `when` names a boolean part on the same sub-item.
   - `read` may use its optional final argument to read the current instance's control values. Keep those values out of Writer props and wire snapshots.
   - `drives: { commands, observe? }` binds a declared phone-tier component or item `press` to a phone-tier component part on the same screen. Use `to: { component, part, instance? }`: an omitted instance requires a unique sibling; an explicit id or `{ prop }` names one. Payloads for `type`, `set`, `select` and `seek` are `{ from: field }` on the source or `{ value }`; `type` replaces a draft unless `append: true`. Only `focus` and `jump` can target `{ self: true, part }`. Declare the destination action and register its addressed ref with `useLocalAnchor`; focus needs a focusable node. Destination offers and values are checked before committing a batch. Destinations that link and controls that require confirmation are not bound. The old string declaration still forwards item-root seeks.
   - To follow a playhead, declare `drives.observe: { from: { component, part, instance? }, at, playing? }` against the sibling's seek part. `at` and `playing` name live props, not Writer props; use `useLiveControls` and `meta.read` to follow the same observation. Supply a composed screen to test sibling bindings rather than a standalone component read.
   - Driven edits target a declared live or linked text input (or `Composer`), a declared setter, or a named selection with explicit choices. Add `siblings: [{ id, c, ...wireProps }]` to a read probe to mount its typed destinations or playback sources with the example.
   - Numeric `set`, `items.set`, `adjust` and `items.adjust` accept `step` and `bounds(holder, props, data)`. The holder is the addressed row or component; `props` reflects staged edits and projections; `data` contains only declared host records. Intersect the returned `{ min?, max?, step? }` with static bounds, or return `undefined` to withhold the control. Steps are anchored at the effective minimum (zero if unbounded). Numeric `KitInput` with `action="set"` and `KitSlider` use the declared live limits. Use a strict revalidated wire schema for cross-field invariants first; only the host settles a remote bid or policy.
   - For an elapsed session without a local-week constraint, use an `up` clock with explicit Start and Stop and `journal: { rows, selection?, validTarget?, lap?, record }`. An optional `lap: { part, max, prop? }` uses a declared press and projects the active lap timestamps. Stop schema-checks one row from `{ start, end, durationMs, laps, count }`, in epoch milliseconds, and cannot append the same session twice. `selection` captures the parsed owner fields; reset discards the active session. For passive `up` and `until` clocks use `timestamp(data, holder, props)` with a host epoch-millisecond value or an ISO timestamp with offset. `up` projects whole seconds and `until` projects milliseconds remaining. Use host scheduling for notifications.
   - `items.nested: { key, parts }` declares `rN/<part>_M` controls projected into sub-items. A part names `action`, `prop` and optional `when` (a boolean part or field on the same sub-item). For `set`, `min`, `max` and `integer` are optional. For `increment` or `decrement`, require `min`, `max` and positive `step`; each is a number or a field name on the sub-item. Step buttons for the same `prop` share one value, clamp at the bounds, and are not offered when they cannot move. Use `useNestedControls` for the live value and disabled state.
   - A nested `select` writes its `prop` from closed `choices`: a static list, `{ prop }` on the sub-item, or `{ prop, from: "parent" }` on the parent. Options can be values or `{ value, label }` and must match the destination field's schema. Use schema-backed row arrays with stable positions, not derived-only rows. Pass the schema as the third argument to `useNestedControls` when rendering without a controller. A nested `press` names its sub-item's subject field as `prop`, but takes no value and does not edit the field. It fires only at an enabled, existing sub-item.
   - Give a nested toggle a `group` and declare its `items.nested.groups` policy. `mode: "single"` replaces the active choice unless it is unavailable; `mode: "multi"` takes `max` as a number or `{ prop }` on the parent. With `by`, each distinct sub-item field value gets its own limit inside the parent. Toggle parts writing the same field share one policy. Read `choices`, `policy.remaining` and `disabled` from `useNestedControls`; do not implement a separate limit in the view.
   - `items.reset` names a declared component `press` that always asks for confirmation. It clears item numeric adjustments and nested steps for this instance back to their input seeds, without clearing other controls.
   - Private handoffs declare `session: { kind: "rounds", items, hidden, reveal, hide, restart? }`. Declare `press` on separate reveal and hide parts for tap mode, or `start` and `stop` on the reveal part for `KitFlip` hold mode. Gate those actions by style if both modes exist. A hide veils and advances in one step, with success on the final hide. `sessionState` gives the view the active row; the agent reading omits `hidden` fields even during a reveal. Declare restart in `confirmParts` and `successActions` if offered after completion.
   - `hostCommands.parts` and `hostCommands.items` bind declared `"part.action"` pairs to a host operation, external handoff, or cancellation. Keep local and host-owned actions distinct; a host-owned action does not also run the local handler or follow `goto`.
3. **`props`**: `z.strictObject`. Every string is `text(n)`, every array has `.min()` and `.max()`,
   icons are `icon`, photos `photo`, links `screenId` (`goto`). Choices are `z.enum([...])` with a
   `.default()` when one is usual. Use shared axes for variants and reserve `style` for structure no
   axis covers. Never colours, sizes, fonts, pixel values or free-form strings for things that have a
   vocabulary.
4. **`fallback({ cast })`**: valid props from the cast only, through the helpers:
   `thingOf(cast)`, `itemsOf(cast, n)`, `titleOf(item, max, thing)`, `detailOf(item, max, thing)`,
   `clip(text, max)`; with nothing usable, `placeholderTitle(i)`, `placeholderDetail`,
   `placeholderLabel`, `placeholderValue`. Never domain words, never a field read by name.
5. **`examples`**: two or more, `satisfies z.input<typeof props>[]`. First Ledge (plant care), second
   Trot (dog walking). Real, specific content at realistic lengths. Together they use every `style`
   and every optional field at least once.
6. **`probes`**: `satisfies Probe[]`.
   - Two or more `choose`: one need this component must win; one near miss whose `expect` is the
     nearest wrong component named in `pick`. Needs are in the person's words and never contain a component id.
   - One `write`: a brief in the person's words; `expect` is this id.
   - One `read` for every component with `actions`.
7. **The view** `export function <Id>(props: Props<typeof props, typeof meta>)`:
   - Built only from kit bases (below). One root base carries `part="root"`; every element that is
     a part carries `part="<name>"` from `meta.parts` / `meta.items.parts`; each item is wrapped by a
     base taking `item={row.id}`.
   - States: `const state = useComponentState()`. `loading` → `<KitSkeleton rows={n} />` in the
     component's shape. `empty` → `emptyLine(useEmptyThing())` in `KitText tone="muted"`. Other shared copy: `goalLine(of)` ("of 5"), `stepLine(at, count)` ("Step 2 of 3"), `totalLine(total, unit?)` ("Total 23 walks"), `trendWord(points)` ("rising"), `stepLabels` (counter buttons), `clockLine(seconds)` ("4:05"), `weekdayInitials` (Monday first), `timerLabels` (start, stop), `streakLine(count, days)` (its read lines), `photoLabels` (add, take, scan). Need other words? Report it; never write literal text in a view. A component whose meaning is in numbers sets `meta.read(props, state)` to return its reading (for example `["3 of 5"]`); it comes before the quoted texts in its read line.
   - No literal user-facing text anywhere. Text comes from props, the cast or `catalog/copy.ts`.
   - No raw numbers for layout. Use `space`, `size`, `radius`, `type` tokens through the bases.

## Host-owned actions

Catalog metadata declares intent; the `PhoneScreen` host owns permission, transport and final settlement.
Without an adapter, host-owned actions are not offered. Ordinary screen links and local controls keep
their existing behavior.

| Need | Declaration and runtime behavior |
| --- | --- |
| Acknowledged command | Bind a declared pair in `hostCommands.parts` or `.items` to `{ kind: "command", name, input? }`. Build bounded scalar fields from validated live props and the addressed row, not from an arbitrary action payload. Match `name` to a host `hostCommands.commands` handler. Its pure `allows` gates offers and execution. Use `partTiers` and `confirmParts` as for other actions. The synchronous `act` reply means the request was staged, not that the host accepted it. |
| Pending and terminal results | Use `useHostOperations()` to draw `pending`, `accepted`, `rejected` or `cancelled` by component or row. Declare `loadingActions` for ordinary controls still offered in a loading state or while that scope is pending. Bind Stop or Cancel with `{ kind: "cancel" }`; for an explicitly `loading` component also list the pair in `loadingActions`. Row bindings require `hostCommands.identity` to return a stable domain key, never a positional `rN`. A new host request replaces the latest result for its scope. |
| Readable acknowledgements | Status is readable automatically for visible scopes. Opt in to individual public fields with `hostCommands.readFields`. Neither the request nor the identity key enters read or wire props. Keep credentials and private inputs out of acknowledgements. The host receives an abort signal; cancellation or unmount does not promise that a remote effect was reversed. |
| External handoff | Bind `{ kind: "external", uri }`, set an explicit non-`phone` tier and provide the host's `hostCommands.external` handler. Only bounded HTTPS URLs without credentials are accepted. Never put a URI in Writer `goto`. A human or agent may request the handoff, but a separate mounted human confirmation is required. The host must enforce platform user activation and its destination policy before opening. |
| Parent admission | Supply the same host `parentGate` to source and protected screens. After the challenge part has mounted, capture `controller.bindParentGatePart(address, destination)` and call it only from the completed hold or private math-input callback. The host verifies the proof and issues a destination-scoped expiring grant. Do not put the answer into Writer props or `act`. A hold does not establish an adult's identity; a link never creates a grant. |

For each declared action, identify whether it is a local control, a shared runtime action, a screen
link or an acknowledged host operation. Test reads and actions from the same live state, with the
host unavailable, and after cancellation or target replacement.
## Actionable collections and slots

Use one parsed, tagged row stream when each row has the same lifetime and ordering and only its
parts or actions differ. Use `meta.collections` when two row sets need independent identities,
actions or selections, even while both are visible. This also works for one durable row set. The
legacy `items` declaration can coexist with named collections. `meta.drives` still means forwarding
an item root press as seek; it does not route collection actions.

| Declaration | Behavior |
| --- | --- |
| `collections.<name>: { key, prefix, identity, parts }` | `key` names a parsed row array. Each prefix is unique and uses lowercase letters and digits, starting with a letter. `identity` names a row field other than `id`; enforce unique stable slugs or positive integers in the schema. The runtime stamps `r_<prefix>_<identity>` as `row.id`. Reserve this pattern for rows. A replacement row needs a new identity; edits, filtering and moves retain it. |
| `actions`, `when`, `visibleWhen`, `toggles`, `select` on a collection | Declare row parts and their actions in the collection, not in `actions.items`. Gates read the row first, then the component; `$first` is relative to that collection. Map `toggle` or `check` parts to boolean fields with `toggles`. `select: { prop, field? }` writes the row id or a unique scalar field to an independent live prop. Use `useLiveControls` for the projected values and `visibleItems(meta, live, name)` for the same rows the reader offers. |
| `slotMoves.<part>: { mode, locked?, allows? }` | Also declare `move` on that item part. `swap` exchanges two occupants; `reorder` inserts the source at the destination index and shifts intervening rows. Send the exact destination row id from `slotMoveOffer(meta, live, name, row.id, part, state)?.move.choices`, passing `useComponentState()` as `state`. A hidden or locked slot cannot be displaced; `allows(row, destination, props)` must accept every displaced occupant. The dispatcher recomputes destinations for each step. The view and reader show the resulting order; Writer arrays and asset files remain unchanged. |
| `KitAction` with explicit `select` or `move` | Use an addressed button inside the item. A closed nested choice passes its value; a named row selection can omit the value. For a direct move button, pass an offered destination id as `value`. |

## Variants

The closed axis vocabulary and its meanings are in [plan 4.2a](implementation-plan.md#42a-shared-variant-axes).
Choose only axes and values that visibly change this component. These are candidates, not requirements:

| Component kind | Typical axes to consider |
| --- | --- |
| Rows and lists | `density`, `surface`, `detail`, `arrange`, `group`, `overflow`, `lead`, `trail`; item `tone`, `mark`, `trail` |
| Cards and content | `density`, `emphasis`, `surface`, `align`, `detail`, `media`, `tone` |
| Numbers and charts | `density`, `emphasis`, `figures`, `labels`, `detail`; item `tone`, `mark` |
| Media | `media`, `aspect`, `bleed`, `detail` |
| Inputs and actions | `density`, `emphasis`, `align`, `detail`, `tone`; item `mark` |

1. Declare ordered subsets in `meta.variants` and row choices in `meta.items.variants`. Put the
   component's existing treatment first so missing props render as before. Omitted `density` inherits
   a supported app setting. Spread `variantProps(meta.variants)` into the strict component schema and
   `itemVariantProps(meta.items.variants)` into the strict row schema. When both declare `trail`, use
   `{ inheritTrail: true }` so a missing row override uses the collection trail; gate actions on
   that same effective value.
2. A finish axis keeps every part and address. A content or collection value declares all part
   changes from the default in `meta.variantParts`, for example
   `{ "detail.brief": { hides: ["body", "meta"] } }`. Never rename or renumber parts or items,
   including hidden items. Pass axis values to kit bases and use `useVariant()` to resolve supported
   settings; bases translate values into theme tokens. Never add raw layout values in a view.
3. To move a legacy style, add a fixture-tested entry in `src/catalog/migrations/variant-line.ts`,
   for example `{ from: "style", values: { compact: { density: "compact" } } }`. Activate it in
   `adoptedVariants` in the same change as the strict schema. Test an old line through `migrateLine`
   and parse the output; preserve ids, actions, and any explicit destination value. Keep a style only
   if the structure still differs independently of the axis.
4. Add one variant-specific write probe for the most distinctive non-finish axis. Ask for the visible
   result in the person's words and assert the requested axis value. Retain existing behavior probes.
   Use realistic examples with content that makes every declared value observable.
5. Run `pnpm look --component <Id>` and review `variants.png` alongside the normal screens. Check
   addresses with render conformance and judge every alternative against the
   [visual rubric](visual-rubric.md#variants-sheet).

See `src/components/Card.tsx` for Card finish and content axes and `src/components/List.tsx` for
List's grouped rows, peek disclosure, inherited trail and per-row tone and mark.

## Promoted core entries

`FilterBar`, `Review`, and `Article` are core. The data, customers and media packs keep their
existing archetypes and JSONL examples with the same component IDs; don't add aliases or re-export
the definitions from the packs. Their words come from the core dictionary.

- `FilterBar` keeps the existing search, picker, active count, sort label and clear action contract.
- `Review` accepts up to three `photos` per review, optional `fitScale` (1–5), `verified`, and
  `spoiler`. Spoilers begin collapsed; a local item toggle reveals or hides review content without
  changing the saved line. The reader must also omit hidden content.
- `Article` keeps its original default layout. It supports `article`, `book`, and `response`
  styles, optional `paper` (light, sepia, dark), and `fontScale` (normal, small, large).
  A line starting with `> [!NOTE]` is a callout.
## Reusing a core renderer in a pack

A view may also import an internal renderer through its kit folder's `index.ts`, such as
`src/kit/timeline`. Pass named, typed data slots, not a second component definition, arbitrary
children or model-supplied layout. The adapter formats copy, resolves variants and state, and
supplies the owner's existing part names and stamped row ids. A missing slot adds no addressed
part; an all-day label is an explicit time slot, not the default for a missing time.

Keep the parent screen/component context. For a bounded list inside an item, use that item's
stamped id and one declared part per position (for example `r1/stop_2`), never a synthetic child
component or item id. Bind actions with the ordinary kit bases to the parent's controller.
The owner keeps fallback, reading, action metadata, live values, tier and host data; even fold
state is resolved by the owner and passed into the renderer.

Keep the strict Writer schema and existing recipes unchanged. Test legacy recipe replay, drawn
parts and action verbs at the old addresses, including hidden or absent slots. The Timeline
pilot shares event rows and date/rail layout without replacing Agenda or Itinerary on the wire.

| Internal renderer | Owner supplies |
| --- | --- |
| `SeatPlan` | Grid sections, optional marker, badges, preview/total and footer; or tables and an unassigned guest tray. Grid targets select or toggle as declared by the owner; table and guest targets retain their separate press/move policies. |
| `StageBoard` | Ordered lanes, localized headings/counts, stamped cards and optional move presentation. Terminal outcomes, locks and eligible destinations are owner policy. A read-only queue passes no move presentation. |
| `FeedRow`, `DateRows` | Named author, timestamp, payload, hierarchy and accessory slots. Date groups preserve the caller's order and distinguish explicit time labels from missing time; independently addressed accessories are not nested in a row link. |

Pass seat activation as `target.action` (`select` or `toggle`); the owner decides which seats
receive a target and when to confirm. Lane destinations carry both their dispatched `value`
and display `label`. To expose a seat or feed action's label or icon as separate parts, name
them in `contentParts`; these recipes do not derive additional address names.

## Words and language

`KitProvider` and `PhoneScreen` take the app's BCP-47 `lang`; the default is English.
Keep built-in labels, units and grammar in `src/catalog/lang/en.ts`, not in views or copy helpers.
Read them with `const { lang, words } = useWords()`; pass `lang` to number, date, time and copy
helpers. Pass the same tag to data-only `meta.read`, `readPrompt`, and `fallback({ cast, lang })`.
Leave authored text, action identifiers, and stored numeric and date values unchanged.

A pack keeps its words in `src/packs/<pack>/lang/en.ts` and exposes its lookup through `lang/index.ts`.
Use `useWords(<pack>WordsFor)` for pack words and `<pack>WordsFor(lang)` outside React.
Use `Intl.PluralRules` via `pluralForm` for counted nouns; thing-type inflection belongs in the
language file. To add a language, write a complete dictionary that `satisfies Words` (or
`<Pack>Words`) and register it with the corresponding language lookup before rendering.
Unregistered words fall back to English. Only English ships at launch.

## Kit bases (the only building blocks)

### Layout recipes

Use `KitHeader` for heading plus supporting text, `KitMetaLine` for a row title and its metadata,
`KitRowGroup` for a shared rail with separators, `KitFigure` for a figure and its caption, and
`KitActionFooter` to attach actions to the group they belong to. The frame sets the outer gutter.
The rail aligns leading and trailing slots; title-to-meta spacing stays smaller than group spacing.
Absent slots take no space unless a row group deliberately reserves the leading rail.

Use only the kit scale: title, body, meta, figure and caption. Existing `KitText` roles and compact
figures map to that scale; use a kit role rather than sizing text in a view. Use `KitState` for
empty, loading, error and success. It takes the same layout in both filled and loading states:
describe the slots once, then let the recipe draw text or inert placeholders. Use an inline status
for operations that leave useful content on screen. Keep existing parts, reading and actions.
Only override a state treatment when the catalog doc calls for it, and do not invent a retry
action. Test the kit geometry separately from host fixture data such as photos.

| Recipe | Slots |
| --- | --- |
| `KitHeader`, `KitMetaLine` | `title`, optional `meta` (one or more lines), `align`, `density`. A line supplies `text`, optional `part`, semantic `role` and finish. |
| `KitLayoutText` | One semantic `line`, with optional `align` and `density`; the same descriptor draws a loading bar. |
| `KitRowGroup` | Row children, optional `leadingWidth="avatar"` to reserve a common rail, `spacing` (`rows` or `groups`), `separators` (default on), `density`. |
| `KitFigure` | `value` and optional `unit`, or `media`; optional `caption`, `align`, `density`. |
| `KitActionFooter` | Action children, optional `align` and `density`. A missing action takes no space. |
| `KitState` | Filled children, optional shaped `loading`, `message`, `part`, `icon`, `density`; `retain` keeps children visible with an inline error or success message. |

Inside a padded frame use `KitRow inset="none"` so the frame owns the gutter. A passive `inline`
row can use `fitContent` to avoid reserving a control-height slot. This never shrinks links or buttons.
In loading, keep the slots and use the inert treatment of `KitLayoutText`, `KitPhoto`, `KitIcon`,
`KitTrail` and `KitAction`; preserve any existing measurement-only addresses.

### Base reference

This table covers every base exported by `src/kit/base/index.ts`, including its exported helpers.
`KitOverlay` is internal to screen rendering, not a component building block.
Folder names below are under `src/kit/base/`; each has an `index.ts` door.
`text` is the lowest layer; `composition` combines bases without lower layers importing it.

For story gestures, pass `holdToPause={{ part, playingLabel, pausedLabel, pauseLabel, resumeLabel }}` to
the advancing `KitAction`. `part` names the mounted component-level `sequence.controls.part` with
`pause` and `play`; the button's own part and action still handle advance. A primary press pauses
immediately if playing, and release or cancellation resumes only that pause. A release inside the
button before 250 ms also advances. The hold works on the last step even when advance is unavailable.
Enter and Space advance, P toggles playback while the web button is focused, and native assistive
technology can invoke the localized Pause/Resume accessibility action. The supplied localized status
labels announce playback without replacing the button's name.

For the step bars, use `KitStepsTrack style="segmented"` with `count`, one-based `at` (add one to a
zero-based sequence cursor), and `progress` (the current step's fraction, default zero). Past bars are
full and future bars empty. The track is decorative; provide a separate readable slide label.
For playhead-driven rows, pass `KitScroll follow={{ address, enabled }}`. Use the mounted child's full
part address (for example, `home/c1/r4/root` for an addressed `KitRow`). The kit reveals the active
child at the nearest edge along the scroll axis without moving keyboard or accessibility focus.
It moves immediately in calm or reduced motion, and on Android where smooth scroll cannot be
interrupted reliably. With follow off, no active address, or during
manual scrolling, updates do not move the viewport. Updates skipped during scrolling are not
replayed; a later address change can follow again after scrolling settles.

Media tokens are 1–128 ASCII letters, digits, underscores or hyphens. Hosts keep bytes, file paths, provider errors and scan details out of Writer props, read output and snapshots. Use a Core Camera or FileList link instead when the component only needs navigation.

Core Composer still requires a text draft. Its accepted send consumes the picked file once and
passes its opaque reference to `onSend`; only replies add a conversation row. Authored attachment
chips are display labels, not picked files. Sent feedback acknowledges dispatch and clears on the next edit.

For a range calendar, declare `meta.dateSpan: { start, end, date, available?, minNights?, clear?, when? }`.
`start`, `end` and `minNights` name component props; `date` and `available` name fields on the day rows.
Use ISO dates and a minimum of 1–30 nights (default 1). Every calendar date from start through end,
including checkout, must be present once and available. Declare item root `select` and the optional
named `clear` press. `when: { prop, equals }` restricts the range to one mode. Read the runtime
endpoints via `useLiveControls` and `meta.read`. Use `dateSpanChoice(meta, live, day.date)` to gate the
drawn day exactly as the dispatcher does. After a completed span the next pick starts a new span;
an earlier available pick moves a pending start, while an invalid end leaves it unchanged.

For an in-screen jump, declare the named part as a normal component `press` and add it to `meta.jump`.
Mount its addressed button and pass that part to the drawing's jump option, or use `useAddressedJump`
for another local anchor. The planner emits a runtime cue only on acceptance. Use `actions.when` if the
destination can be absent. A local jump does not inherit the component's `goto`. Native hosts supply
`NativeHost.focusAccessibility(element)` to move the screen reader to a revealed anchor. Keep board marks in `meta.read`, and
gate unavailable seat and cell actions using the same facts that determine their drawing.

## Tests: `<Id>.test.ts`

Copy `List.test.ts` and keep its four blocks: every example parses; invalid inputs are rejected
(over-long text, too many or too few items, unknown enum values, unknown keys, raw colours); the
fallback validates with an empty cast, a cast with matching things and a malformed cast, and uses
placeholders when empty; probes are well-formed (a `codeOwned` component, built by code and never by the model, has only `read` probes; otherwise ≥2 choose with a near miss, 1 write, read if
actions). Rendering is covered by `test/conformance.test.tsx` automatically.
A test that renders a component uses the shared `config` and `renderInstance` from `test/render.tsx` and never calls `createTamagui` itself: it registers a global config, so two copies clash ("Missing theme").

## The model gate

`pnpm llm:check --component <Id>` must print `All required probes pass.` before the component is
done, and the recordings it writes under `test/recordings/<Id>/` are committed. `pnpm test` replays
them. Each probe is sampled 3 times and passes on a majority (2 of 3); a probe that passes 2 of 3 is
printed `unstable`. Run it once per change and never re-run for a luckier result. If a probe fails or
is unstable, improve this component's `purpose`, `pick`, `writeHints` or limits (or the example) and run
again. Never weaken a probe, and never edit another component to make yours pass;
report the conflict instead. A `choose` probe whose expected component is not built yet is skipped.

## Done means

All of these pass from the repo root: `pnpm format:check`, `pnpm typecheck`, `pnpm test`,
`pnpm build:catalog`, `pnpm llm:check --component <Id>` (choose, write and read probes), and
`pnpm look --component <Id>` prints `No issues.` The reading test (`test/reading.test.tsx`) proves
the text a model reads matches the screen and that every offered action exists with the right role;
a part that exists only for some prop values declares it in `actions.when`. An item rule reads the item first, then the component's props; a key `part.action` limits one action (`"root.toggle": { style: "filter" }`); `$first: true` matches only the first item. A component that draws only its first item (a card stack) sets `items.visible: "first"`: the reader reads it and adds "+N more", and conformance expects only `r1` on screen.

Then the look must pass `docs/visual-rubric.md`: look at every PNG yourself, then get the
`ui-reviewer` subagent (`.factory/droids/ui-reviewer.md`) to review it with fresh eyes, fix, and
repeat until it answers `APPROVED` (at most 3 rounds). The orchestrating agent then looks at the final
screenshots once, approves and merges.

For pack acceptance, start with `pnpm look --component <Id> --widths 390 --preset calm --mode light`.
Use the part names in `issues.json` to find the source. Use tight spacing inside a label/value
pair and more space before the next group; put the first row close to its heading. Use at most
three text sizes per item, and use end alignment for numeric columns even with tabular digits.
Use a danger or neutral treatment for negative actions rather than the primary accent. Check
that meaningful text fits without clipping or ellipsis; a wholly offscreen item in a scroll
region is not clipped text. When the component brief requires a specific empty message, pass it
from the language copy to `KitEmpty` instead of letting it show the shared neutral line.

Document this requirement on the component's `States:` line as `empty (reason)` in its catalog
brief. The acceptance reviews also call for specific copy in these existing cases:

- `Approval`: empty (no requests waiting for a decision).
- `TravelDocs`: empty (no travel documents).
