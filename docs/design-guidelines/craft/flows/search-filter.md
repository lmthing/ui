# Search and filter: keep query, scope and results legible together

- **Idle → typing:** Put search in the main navigation if it is a primary app goal, or within an explicitly named local scope. Keep a persistent accessible label whether or not the field has a placeholder. Show recent/suggested searches only if helpful, with a clear-history option when retaining recent terms is appropriate. Keep typing in place; debounce remotely queried results if appropriate (about 200–300 ms to start), suppress outdated replies, and don't delay direct input feedback.
- **Filter:** Show current query, scope and active filters above the results. Give chips a selected state and removable criteria an individually named control. Use instant filters for cheap, reversible changes; use a draft Apply/Reset/Cancel sheet for complex or remote filters. Keep draft filters separate from applied ones and state what Reset affects. At 390, wrap a small group or provide a reachable visually evident “Filters (3)” button rather than hiding controls offscreen.
- **Result → return:** Distinguish first empty, loading, no matching results, stale and failed. Preserve query and active criteria in every state. “No results for ‘oak’” plus Clear filters or Change query is different from an outage. When someone opens a result and returns, restore query, filters, selection and scroll. Announce a settled result count politely, not every character.

Apple differentiates search across the app from searching a specific view and offers system search placements that can open above the keyboard. Material distinguishes filter chips from suggestion, assist, and input chips. On web use platform text/search controls and combobox semantics only when there is a suggestions popup; provide arrow navigation, Enter and Escape behavior, including focus return from an advanced-filter modal. On native use system text entry and respect back-to-dismiss for the keyboard before leaving a search context when appropriate.

**For lmthing:** `Search` handles query, `FilterBar` already covers active count/picker/sort/clear, `Chips` handles local choices, `List`/`Gallery` shows results and `Empty` or `Banner` explains outcomes. Gap: exercise scope change or rapid filter changes with out-of-order responses, no results vs transport error, and query/scroll restoration in a browse recipe.
