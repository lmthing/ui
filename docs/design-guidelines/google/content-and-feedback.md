# Content, overlays and feedback

Choose containment by what the user needs: show subjects in cards or rows, optional actions in a menu, supplementary detail in a sheet, mandatory decisions in a dialog, and routine outcomes without interrupting the job. A different container changes focus and navigation, not just appearance.

## Cards, lists, dividers and carousel

| Component    | Anatomy and variants                                                                                                                                                                                                                                                                         | Use at 390, and what not to do                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Card**     | One subject; container, title/supporting text, optional media, actions. Filled, outlined and elevated. Baseline medium radius 12 dp; elevated baseline level 1.                                                                                                                              | Lead with the identifying content. Start with a 16 dp inset as a working example; make repeated image ratios and action placement consistent. Use one main card action and distinguish any secondary control semantically; on web never nest a button in a fully interactive button/link. Prefer a row if subjects are uniform and scanning matters more than imagery.                                                           |
| **List**     | Leading image/icon/control, primary label, optional supporting or overline text, trailing value or independent control. Baseline or segmented grouping in current guidance.                                                                                                                  | Expressive references 56/72/88 dp minimum patterns depending on content; top-align at 88 dp or when text reaches three lines. Let text grow, keep metadata aligned, use selected/pressed/focus states, and reserve the full 48 dp for separate trailing actions. Never put a link, selection and toggle on the same undifferentiated row target.                                                                                 |
| **Divider**  | Full-width or inset line, usually 1 dp visually, between logical groups or across substantial regions.                                                                                                                                                                                       | Align inset dividers to content, not arbitrarily; use whitespace as the first signal, especially between distinct groups. Avoid borders around every row plus repeated dividers. Use only visual separators unless the structure needs a semantic break.                                                                                                                                                                         |
| **Carousel** | Items in a horizontal or vertical scroll area, optional controls and position. Multi-browse has large/medium/small; hero has a large and small; centered hero has small on both sides; uncontained can clip at the edge and supports multiple aspect ratios; full-screen scrolls vertically. | Prefer snap for hero/multi-browse/full-screen; free scroll is suitable for uncontained. At 390, avoid more than three multi-browse items unless recognizable. Only uncontained deliberately clips past the edge; a small fully visible hero neighbor hints that more is coming. Provide **Show all** or equivalent vertical access on a vertically scrolling page. Don't put essential text inside a crop or force auto-advance. |

Hover is supplemental. For web ensure ordered navigation, keyboard access to the last item, and reduced motion for programmatic scrolling. On native provide tap alternatives to swipe-only actions and keep carousel gestures from blocking vertical scroll.

### For lmthing

Use `Card`, `Hero`, `List`, `FileList`, `Gallery`, and `List[shelf]` rather than one oversized rich card for every record. Listings in marketplace, places and events need discoverability without tiny labels. Gap: a `Show all` and keyboard path in shelf/gallery recipes, segmented list treatment behind kit, and row/trailing target and text-growth fixtures.

## Menus, dialogs and sheets

| Component        | Anatomy, states and variants                                                                                                                                                                                                                                          | Choose it when                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Menu**         | Anchor, surface and ordered action/choice rows, optional leading icon, shortcut or check, and one or two group gaps or dividers. Standard is surface-based; expressive vibrant uses tertiary. May be contextual or nested on larger windows. Rows have 48 dp targets. | A short set of immediate actions or choices. Position by available space, keep the anchor visible if possible, dismiss for single actions; multi-select can remain open. Keep one action per row. At 390, convert a cramped anchored menu to a bottom sheet. Web needs keyboard traversal, Escape and focus return; long press/right-click must not be the only way in.                           |
| **Dialog**       | Scrim, optional icon/title, concise supporting copy or input, explicit actions. Basic dialog; full-screen dialog for a larger, separate task on compact.                                                                                                              | The person must decide or finish something before continuing. A compact baseline basic Compose dialog accepts roughly 280–560 dp width; leave margins and let text wrap. Make the safe exit easy, name the consequence, focus appropriately and keep background inert. Don't use for routine success or inline errors that should sit near the field.                                             |
| **Bottom sheet** | Bottom-anchored surface, 28 dp top corners; optional handle, title, content and actions; standard/nonmodal or modal with scrim. Can be partial or expanded.                                                                                                           | Supplement the current task on compact: options, details, actions. Let content scroll independently and keep bottom safe/keyboard insets. For modal sheets provide an explicit close in addition to gesture/back as appropriate, prevent background interaction and restore the opener; for nonmodal preserve usable background. Don't stack blocking sheets or use them as arbitrary navigation. |
| **Side sheet**   | Leading or trailing side surface, usually trailing to avoid leading navigation; title, optional back/close/actions, content and optional dividers. Standard or modal. M3 allows 16 dp inset for a floating treatment.                                                 | Supplement a wider workspace with parameters, details or editing. Prefer bottom sheet or separate page on a 390-wide phone unless a side sheet genuinely fits. Only modal variants trap focus; standard panels need reachable controls and clear reading order.                                                                                                                                   |

Make enter/exit show the relationship to the anchor, not a generic page push. Animate surface and scrim separately when suitable. Keyboard and system back close only the topmost surface; drag dismissal must not mutate an uncommitted selection or draft. Modal semantics and actual pointer/keyboard access must agree on both platforms.

### For lmthing

`Sheet[menu|picker|detail]` and `PhoneScreen` already provide one overlay slot and focus restoration; `Button` confirmation is code-owned. Prefer full screen when the content demands a real task rather than adding modal layers. Gap: reusable anchored-menu and wider-pane recipes that preserve addressed actions, keyboard focus, and the existing restriction on covered controls.

## Snackbar, badges and tooltips

- **Snackbar:** Low-priority bottom status, optionally one short action such as Undo and a dismiss affordance. Material suggests a 48 dp single-line or 64 dp two-line compact body, expanding if needed; place above nav/FAB/insets. Only one visible at a time. Passive native feedback may time out in 4–10 s (platform-dependent); M3 recommends action snackbars remain until dismissal, and on web avoid timed-only feedback without a persistent inline equivalent. No hidden commitment or required next action in a disappearing message. Announce politely without stealing focus.
- **Badge:** Dot for a newly present state; numbered badge for a meaningful count (common baseline sizes are 6 dp dot and 16 dp minimum with label). Overlay the parent's icon or status anchor without covering its silhouette. The parent announces meaningful count/state once, not two stops. Use the appropriate abbreviated count if there is insufficient space, keeping the real count accessible when useful; badges aren't standalone buttons or progress meters.
- **Tooltip:** Plain for a brief label; rich for added context with optional subhead/links or actions. Anchor to the control; plain offset 4 dp from a visible boundary or 8 dp without one, then reposition to keep in view. Make web plain tooltip available on keyboard focus as well as hover, dismissible on Escape, hoverable, and persistent until trigger/tooltip loses interest or user dismisses it. Put actionable rich content in a focusable popover/dialog pattern, not an ARIA `tooltip`. Long press on touch can supplement, never be the only explanation for an essential action.

### For lmthing

`Success[toast]`, persistent `Banner`/`Success`, `TabBar` counts, and `Card`/`List` badge parts are distinct. A status must be a durable fact in the component read, not merely a fading bubble. Gap: persistent undo policy where possible, status announcements, tooltip trigger parity and real controls above keyboard/pinned bottom.

## Loading and progress indicators

- **Expressive loading indicator:** Indeterminate short wait, often morphing, optionally with a container. M3 suggests no indicator below 200 ms, a loading indicator for about 200 ms–5 s, and a progress indicator for longer waits. Default indicator size is 48 dp; guideline range 24–240 dp based on context. At 390 keep it local to the initiating control/region; don't cover readable prior content to animate a spinner.
- **Progress indicators:** Linear or circular; determinate when there is a reliable numerator and denominator, indeterminate if the end is unknown. Expressive adds wavy forms; on a determinate linear bar the 4 dp stop marker indicates its endpoint. Show a label/unit for a meaningful measured value; a long process needs an honest state, optional cancel if supported, and recovery on failure. Never show fake percentages or convert unrelated waiting into a loop on every card.
- **Implementation:** Keep placeholder and final geometry coherent; do not announce progress on every frame. Use an accessible progress value only if determinate and expose a readable status separately. Update the visual and accessible value without disturbing focus; in reduced motion, static informative text or a restrained non-travel cue can replace the shape cycle.

### For lmthing

`Progress` is measured goal data, not a universal activity spinner. Use kit skeletons/`loading`, `Timer` for a meaningful clock, `Empty` or `Banner` for retry, and `Success` after confirmed completion. Gap: shared slow-wait escalation, cancellation and reduced status announcements rather than bespoke timers in each network-backed pack.
