# Lists, tables, collections, and paging

## Match arrangement to information

| Family | Anatomy and variants | What to check at 390 wide |
| --- | --- | --- |
| List | Section heading, row label, optional lead and secondary text, optional trailing value or accessory. Use a disclosure chevron for navigation and an expansion affordance for in-place detail. | Reserve the trailing control's target, align the rest of the rows, and grow height for larger text. Highlight an activated row promptly; show persistent selection only when the item remains selected. If it has swipe shortcuts, offer the same commands through visible or accessible controls. An info button reveals information, not generic row navigation. |
| Table | Named columns and aligned values with comparable units; iOS also uses table views for vertically scrolling rows. Plain, grouped, or inset-grouped presentation can distinguish density and sections. | For mostly text or an item with one primary value, start with a list. For true cross-row comparison, retain tabular semantics and right-align comparable numbers. At small size offer a reduced column set or well-labeled horizontal scrolling for inherently two-dimensional data, not clipped values. Don't combine a trailing index with a column of trailing row controls. |
| Collection or grid | Repeated cells with predictable sizes and image, title, and metadata slots; row, grid or media rail depending on how people browse. | A two-column design with 16-unit side gutters and a 12-unit gap leaves 173 per tile; collapse to one when meaningful labels or actions no longer fit. Keep item identity through insertions, deletions, and reorder so the person can track what moved. Don't reorder browse results under a stationary finger. |
| Disclosure or grouping | Use labeled expandable sections for optional content; use a box only when it adds a useful boundary. Secondary disclosure is not the primary hierarchy. | Keep the control adjacent to its content, expose expanded state, and retain focus on collapse. Keep heading with its first item. Avoid nested cards around every row. |
| Page control | Equidistant indicators for an ordered set of peer pages, current indicator distinct, normally centered below. iOS supports automatic, prominent, and minimal backgrounds. | More than roughly 10 dots is hard to parse; use a grid or an explicit selector for many peers. Provide an accessible `Page 2 of 5` value and non-swipe controls. Transition on tap, but don't animate every intermediate page during scrubbing; minimal style is for position, not scrub feedback. |
| Scroll view | Viewport, content and scroll indicators or other affordances; can support paging, zoom, or scoped horizontal media. | Prefer one vertical owner; don't nest a second vertical scroller as a default. Show that a rail continues without hiding required content. Bring a search result, insertion point, or focused control into view without moving unrelated focus. |

A concise label can name a row, a text view handles longer or editable content, and an image view is for images rather than a substitute button. Make meaningful text selectable where useful. A chart needs the takeaway and unit as well as plotted marks. Start bars at zero when their length encodes magnitude, use line marks for trends, and provide a readable summary or table plus keyboard and screen-reader access; don't make the important value discoverable only by scrubbing. A loading placeholder should preserve relevant columns and media slots; an empty list should state why there are no rows. Neither should emit pretend actionable or readable rows.

Native lists and collections provide expected scrolling, selection and editing conventions. On the web use real list and table structures where applicable; a CSS grid is not inherently an interactive ARIA grid. Test keyboard traversal from first to last element, and preserve DOM/reading order even in visually staggered layouts. For virtualized long collections, verify focus and announcements as cells are recycled.

## For lmthing

Use core `List`, `KeyValue`, `Gallery`, `Photo`, `Timeline`, `Bars`, and `Sparkline` with the component guide's shared layouts and skeletons. `KitListItem` already has multiple row patterns; add an option only if it answers the same need and keeps part identity. Treat generic table comparison, system-quality pagination of `Gallery`, and keyboard/accessibility support for reordered pack grids as gaps to audit. Review commerce `ProductGrid`, curation `PinGrid`, and progress/data-heavy packs against the visual rubric's alignment, last-column reach, and repeated row rhythm.
