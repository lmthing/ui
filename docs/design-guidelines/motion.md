# Motion system

Motion answers **where did it come from, what changed, or what happens next?** Apple informs touch continuity, interruption and reduced motion. Material informs a shared vocabulary for spatial moves versus opacity/color effects. lmthing uses both, with one explanatory moment at a time and familiar, quiet behavior for ordinary work.

## Tokens and profiles

The source is [`tokens/motion.ts`](../../packages/ui/src/catalog/tokens/motion.ts) and [`kit/motion`](../../packages/ui/src/kit/motion/README.md). Values below describe token use, not values to author in views or model props.

| Theme motion                               | Timing and easing                                                                                                                                                           | Spatial spring use                                                                                                                                    |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `calm` (default)                           | `fast` (120 ms) effect or cut for micro-feedback; `base` (220 ms) where a local relationship needs time; no decorative delay. Time-based kit interpolation is linear today. | `gentle` (180 stiffness / 24 damping) for a restrained arrival, `snappy` (420 / 34) for local settle or layout change. Avoid conspicuous rebound.     |
| `lively`                                   | Same `fast`/`base` tokens for controls; reserve `slow` (420 ms) as the nominal token for a single deliberate reveal. Use the same linear effect path today.                 | `gentle` for broad movement, `snappy` for direct settle, `bouncy` (300 / 14) only for an earned playful cue, never authorization, payment or failure. |
| Reduced motion (override, not a wire enum) | Cut or short `fast` crossfade with no stagger. Status, focus and the next action still update.                                                                              | No spatial travel, scale, sweep, animated counts or momentum. A progress value can step to its actual value.                                          |

Spring values are coefficients, not milliseconds; a spring settles when it converges. Never wait for its tail before accepting input. Spatial motion uses springs; opacity never overshoots. Named timed easing curves, consistent profile-specific selection and effect/spatial separation are kit gaps, not license to add bezier numbers in a view. The host/provider projects reduced motion; `themePreferencesOf` maps reduced preferences to `calm`. Currently `KitMotion` mostly keys off reduced/agent mode, not the theme enum: shared gentle arrival with 8-point rise and 40 ms stagger, capped by index 5 (200 ms maximum delay); `fast` exit fades and collapses; layout changes use `snappy`. Reduced arrival loses the rise but currently retains stagger and exit collapse. Audit preference propagation independently in both profiles; agent mode is an end-state path, not proof of reduced motion.

## Transition catalogue

| Relationship                     | Treatment to choose                                                                                           | Boundary                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| First screen / restored screen   | Complete static first view; only animate a subsequent meaningful change.                                      | Never mount a working screen at zero opacity or replay reveal on routine remount.                                                      |
| Peer tabs or unrelated results   | Cut or fade through with navigation and search scope fixed.                                                   | Do not imply chronological order.                                                                                                      |
| Push, pop, ordered step          | Host Back/forward; where kit owns the move, one meaningful axis and coherent reverse.                         | Parent keeps scroll and focus; no app-level slide that fights system gestures.                                                         |
| Same record to detail            | Anchor a title, thumbnail or status to the same domain record; fade in new labels at final type size.         | Shared-element matching is a proposal; addresses alone are not identity. Without both measured endpoints use ordinary navigation/fade. |
| Sheet/confirmation               | Keep source context, enter from its affordance or sheet edge, dismiss back to the initiating control.         | Modality requires a scrim, correct focus and inert background; no confirmation on mere release or dismiss.                             |
| Insert/remove/reorder/expand     | Move the affected group about one stable edge; a removal may use local keyed `KitPresence` while visual-only. | Never animate every unchanged row, duplicate a moved item or leave an exiting control focusable.                                       |
| Loading to content, error, empty | Keep the original geometry for pending content where possible; replace the smallest relevant region.          | A genuine progress indicator may update; don't run idle decoration or fake progress.                                                   |
| Pending to success               | Acknowledge press immediately, show actual pending, then give a single state cue on accepted result.          | Pending, cancellation and rejection do not play a celebration.                                                                         |

## Choreography, feedback and gestures

1. Keep the title, origin object or amount fixed. Show immediate press/focus feedback, commit the semantic state, then move only the changed surface and reveal detail. At most one visually dominant movement per screen.
2. Sequence only a few groups when order means something. Prefer the existing 40 ms token for up to four visible groups (120 ms first-to-last); later rows stay still. Never delay primary content behind a stagger. Keep scroll, focus and interactive targets independent of the decorative timeline.
3. Selection uses a persistent selected mark/label plus a small local cue. A reversible local action may offer Undo. Show genuine progress with units or persistent waiting text; show a final result once and keep its label after the motion. Sound or haptics are optional host enhancements and never the only feedback.
4. Direct manipulation follows the hand with no playback easing. Resolve scroll-versus-drag intent first; keep one owner (stage or component). Release settles toward the intended reachable state, cancel restores the source, and new input/Back wins during settle. Preserve position and velocity on retarget where supported; `animateNumber` currently starts a fresh spring at zero velocity. Provide keyboard/tap alternatives; cancel frames/timers on teardown and exclude visual exits from hit testing and the accessibility tree.

## Signatures and contract

[`signatures.ts`](../../packages/ui/src/catalog/signatures.ts) registers `ring_fill` (Progress), `bars_grow` (Bars), `check_burst` (Checklist), `count_up` (Stats), `calendar_sweep` (Calendar), `timer_spin` (Timer), `card_swipe` (SwipeStack), `day_unfold` (Timeline hours), `streak_flame` (Streak) and `route_draw` (Route). Registry duration is nominal; `useSignatureProgress` drives registered hooks with the spring. Use an eligible signature once on a meaningful cue, not on scrolling/remount; showing the end value immediately is the reduced/agent fallback. A signature never owns navigation, the result, or an action address.

Every component contract names **enter, change, feedback, exit and reduced motion**. For each, record trigger, what stays anchored, moving part and kit token/profile (or “none” and why), effect on focus/actions, interrupt/cancel behavior and terminal visual/semantic state. Example: a queue's first view is a cut; an explicit expansion keeps the row title fixed while detail reveals; selection names status immediately; collapsing removes the detail's targets before exit; reduced motion switches detail without spatial motion. Include the source/mid/destination/return evidence in the [rubric](rubric.md). Do not implement motion in individual views when it belongs to a shared base.
