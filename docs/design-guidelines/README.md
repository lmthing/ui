# Design guidelines

One lmthing design runs on iOS, Android and web. These rules govern components, archetypes and generated screens. They take precedence on design questions; the [component guide](../component-guide.md) still governs code, addresses, schemas and model gates.

Start with the person's job and the result they need to trust. Choose a flow or archetype, then component families and closed options. Write the motion contract before implementing a transition. Inspect the 390-wide light baseline and the actual sequence, including cancellation and reduced motion; record missing evidence rather than calling the behavior verified.

The [Apple](apple/README.md), [Material](google/README.md) and [craft](craft/README.md) notes explain where the decisions came from. They're research, not parallel rules. The [catalog](../catalog/README.md) and kit source tell you what's available today; recommendations marked as proposals or gaps aren't wire options.
